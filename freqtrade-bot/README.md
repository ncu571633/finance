# freqtrade-bot

My crypto trading bot. **Only my own work lives here** (strategies + configs + docs); the
Freqtrade engine is installed from PyPI (`requirements.txt`), not vendored. Stage:
**backtest / paper (dry-run) research only — no real money.**

Focus: trade **BTC + ETH only** (largest, most liquid, can't delist). Full analysis,
backtest numbers and conclusions are in **[`RESULTS.md`](RESULTS.md)** — read that first.

## 📁 Repository map (what every file is for)

### Strategies — `user_data/strategies/`
The part I own: each is a class with `populate_indicators` / `populate_entry_trend` /
`populate_exit_trend`. ✅ = keep/use, ❌ = reference/cautionary only.

| File | Timeframe | What it does | Verdict |
|---|---|---|---|
| `BTCETHCombo.py` | 4h + daily gate | 4h swing, only when daily price > 200-day SMA | ✅ **Main pick** — best risk-adjusted (+68%, −26% DD) |
| `BTCETHSwing.py` | 4h | Momentum: hold while EMA50>EMA200 & price>EMA50 | ✅ Highest return (+78%), biggest swings |
| `BTCETHTrend.py` | 1d | Hold while price > 200-day SMA, else cash | ✅ Most hands-off (+57%, holds weeks–months) |
| `BTCETHIntraday.py` | 15m | RSI dip + 1h trend filter, quick exits | ❌ Day-trading — lost −42%; proof it doesn't work |
| `RSIMeanReversion.py` | 5m | Textbook RSI<30 buy / >70 sell | ❌ Naive baseline (−0.93%, fees kill it) |
| `SampleRSIStrategy.py` | 5m | Project sample (RSI<30 AND close>ema50) | ❌ Makes 0 trades (conditions never co-occur) |
| `NostalgiaForInfinityX8.py` | 5m | Downloaded community strategy (52k lines, alts) | ❌ Alt-rotation; makes 0 trades on BTC-only |

> public-data mirror) to bypass the HTTP 451 geo-block on `api.binance.com`. That endpoint
> is **data-only — it cannot place orders** (fine for backtest/dry-run simulation).

## Setup

```bash
python -m venv .venv                        # Python 3.10–3.13
.venv\Scripts\activate                      # Windows  (Linux/Mac: source .venv/bin/activate)
pip install -r requirements.txt             # install the engine
```

No API keys are needed for backtesting or dry-run (data comes from the public mirror).

## Run (recommended = the Combo strategy)

```bash
# 1. Download data (BTC + ETH, all timeframes the strategies use)
freqtrade download-data --config config-swing.json --pairs BTC/USDT ETH/USDT \
  --timeframe 5m 15m 1h 4h 1d --timerange 20200101-

# 2. Backtest
freqtrade backtesting --config config-swing.json --strategy BTCETHCombo --timerange 20240101-

# 3. (later) paper-trade with live prices — dry_run:true => simulated orders
freqtrade trade --config config-swing.json --strategy BTCETHCombo
```

Swap `--config` / `--strategy` per the tables above to run the others.

## Guardrails (learning stage)
- Keep `dry_run: true` everywhere. Never grant API withdrawal permissions.
- Backtest profits ≠ future profits — see the honest caveats and the 2022–2023
  out-of-sample test in [`RESULTS.md`](RESULTS.md).
- No real money until a strategy holds up in dry-run over **months**, not a week.
